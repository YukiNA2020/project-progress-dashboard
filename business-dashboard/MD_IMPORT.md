# MD 导入规范

这份文档解决一件事：**让公司那套 AI 把云邮件、云群聊整理成看板能吃进去的 Markdown。**

本地解析器认的是结构，不是文采。公司 AI 越少加工，导入就越准；它一旦"帮你总结"，原文里的日期、型号、卡点就会被改写成读不出来的散文。

---

## 一、直接复制给公司 AI 的指令

```
请把我给你的邮件和群聊记录导出成 Markdown 文件，严格按下面的格式，
不要总结、不要改写、不要合并、不要加任何分析和建议。

格式要求：

1. 文件开头可以有一个 # 标题，随便写。
2. 每一封邮件、每一段群聊记录，单独成为一个二级标题块，格式：
   ## YYYY-MM-DD 来源 · 简短说明
   其中"来源"只能是：邮件 / 群聊 / 会议 / 电话
3. 每个二级标题下面，先写三到四行元数据，一行一个，用 - 开头，中文冒号：
   - 客户：客户名称或代号
   - 型号：产品型号（如 X220）
   - 来源：邮件 / 群聊 / 会议
   - 发件人：姓名或部门
   - 主题：邮件主题原文
4. 元数据之后空一行，然后放正文。正文保持原文，不要改写成第三人称，不要删细节。
5. 原文中的引用部分，用 > 开头保留。
6. 日期一律写 2026-11-20 这种完整格式，不要写"周三""上周"。
7. 一个型号一段。同一封邮件提到三个型号，就拆成三个二级标题块，
   每个块的元数据里写对应的那个型号。

如果某封邮件信息不全，缺的元数据行就不要写，不要填"未知"。
```

最后那句很关键：**缺的就不写**，比填"未知"好处理——填了"未知"会被当成客户名。

---

## 二、一个合格的样子

```markdown
# 本周项目进展

## 2026-11-20 客户邮件 · PI 更新
- 客户：客户A
- 型号：X220
- 来源：邮件
- 发件人：采购 玛丽
- 主题：PI revision - X220

客户确认 X220 涨价，需要重做整单 PI，签章后回传。
计划 12/17 前完成生产，1/15 发货。

> 上一版 PI 已于 11/10 收到，请以新版为准。

## 2026-11-21 群聊 · 滚动计划
- 客户：客户A
- 型号：X200
- 来源：群聊
- 发件人：计划部

滚动计划今天必须提交，工厂要 T+4 周才排得出来。
模具要改，卡在开发那边还没给包装书。

## 2026-11-22 群聊 · 第二笔订单
- 客户：客户B
- 型号：D30
- 来源：群聊

第二笔订单 1 月底下，船期不能和第一单撞，客户库存会积压。
```

看板会从这三个块里读出：三段记录、两个客户、三个型号、两个已有型号可匹配、三个日期节点（12/17 生产完成、1/15 发货、1 月底下单）。

## 三、什么写法读不出来

| 公司 AI 常见的加工 | 结果 |
|---|---|
| 把"12/17 前完成生产"改成"12 月中下旬完成" | 认不出日期，日历上没有这个节点 |
| 把"客户A"统一改写成"该客户" | 客户名对不上，只能新建一个"未识别"客户 |
| 把三段记录合并成一段综述 | 型号丢失，三条进展只会落在一个型号上 |
| 用表格代替元数据行 | 能读，但可靠性差；`- 客户：xxx` 最稳 |
| 只写"周三""下周一" | 可以推算，但跨周容易错，尽量写绝对日期 |
| 在正文里加"建议我们尽快跟进" | 会被当成"下一步动作"抓进去 |

---

## 四、格式写不出来怎么办

如果公司 AI 死活不肯按格式输出，只要满足下面三条，导入依然可用：

1. **一个型号一段**，段与段用 `##` 分开
2. 每段开头有 `- 客户：xxx` 和 `- 型号：xxx`
3. 正文保持原文，日期写完整

其余（来源、发件人、主题、引用）都是加分项，缺了不影响主流程。

---

## 五、本地怎么用

1. 看板 → 录入 → 导入 MD
2. 拖文件进去，或直接粘贴
3. 点「解析」→ 右边列出每一条候选
4. 点任意一条，左下会显示**它依据的是原文哪句话** —— 这是核对关键，别跳过
5. 确认勾选，点「合并到看板」

合并规则：

- 认得出客户 + 型号，且看板上已经有这一行 → **追加进展**（阶段只会往前走，不会被旧邮件拉回去）；同一天已经有的时间点不会重复加
- 认不出对应型号 → **新建一行**
- 同一份 MD 再导一次 → 那条会被标成「已导入过」，而且不能勾选

判断"是不是同一件事"靠的是**内容哈希**：每段正文算一个指纹存进项目日志。所以改了正文再导，会被当成新的一条；完全一样的，直接跳过。

---

## 六、第一次试的时候

先别导全量。挑一封信息最全的客户邮件，导进去，看两件事：

1. **五行元数据有没有被认出来**（客户、型号、来源、发件人、日期）
2. **点开那条候选，原文依据对不对**

这两个对了，剩下就是量的差别；不对，把那段 MD 贴给我，我调规则。
