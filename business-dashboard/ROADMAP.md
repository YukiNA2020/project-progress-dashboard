## P0.5 · 盘点向导（可选，看你判断）

明天你的真实任务是"把 5～6 个项目的状态理清楚"，这是一次性盘点，不是日常录入。如果今晚还有余量，做这个的收益比打磨解析更高。

**形态**：首页顶部加一条「盘点进度 3/6」，进入后按项目逐个过四问：

```
项目名 → 现在什么阶段 → 卡在什么事上 → 下一步谁在什么时候做什么
```

每个问题一个输入框，回车即下一题，答完自动存档。全部走完给一页「盘点小结」，可截屏/打印。

**做与不做的判断**：如果你明天打算"边想边录、录完再看全貌"，就不需要向导，直接用手填表单（表单已够快）。如果你担心"坐下来不知道从哪个开始问"，向导价值很大。

我倾向 **P1 再做**——明天的真实瓶颈是"你还没想清楚项目状态"，不是"工具不好用"。工具别抢戏。

## P2 · 智能化（前提：合规方案先定）

**前提条件（任一不满足就不做）**：

1. 有明确的脱敏方案并通过自查（客户名 → 代号映射，本地还原）
2. 使用者能接受"这几段文本会发到外部服务商"并在界面上逐次确认
3. 失败必须降级回本地解析，不能阻塞录入

内容：

- LLM 解析（provider 抽象已预留，支持 OpenAI 兼容端点 / Anthropic）
- 解析质量评估：用 `captures` 里 `parsed` vs `apply` 的差异算字段准确率，只对低分字段走 LLM
- 项目状态自然语言问答（"哪些项目这周要交货"）

---

## P3 · 明确不做

| 事项 | 理由 |
|---|---|
| 多用户 / 角色权限 | 单用户场景，成本远超收益 |
| 云同步 / SaaS 化 | 客户数据不可出内网，这是硬约束 |
| 移动 App | 网页版足够，不值得维护第二个端 |
| 与公司 ERP/OA 对接 | 需要 IT 审批与接口权限，不在个人工具范围 |
| 成本/毛利核算 | 最高敏感数据，个人工具不应承载 |
| 自动抓取邮件/微信 | 需读客户端数据库，合规风险高 |
